# 製品の範囲

ひまっち（仮）は、自分も相手も予定を入れたい時間を「暇時間」として登録し、友達への招待と参加OKを通じて予定を調整するアプリです。
初版のiOSは日本向け・18歳以上・既知の友達5〜20人による招待利用を想定し、15分単位の暇時間、招待、部分回答、安全機能、アカウント削除を扱います。予定の最終確定は後続工程です。
Backendは公開契約・認可・複数ユーザー整合性・実削除を所有します。Sign in with AppleをSupabase Authへ接続し、プロフィール、友達関係、本人の暇のOR統合・区間削除、招待の送信・受信・回答・取消を実 Backend 境界として扱います。最初の内部TestFlightはstaging Supabaseとstaging APIへ接続します。Push配信と予定確定は後続工程です。

| 領域 | Backend の実装時の配置（src 配下） | 現時点で読み取れる責務 |
| --- | --- | --- |
| 認証 | `src/Auth/` | 認証に関する処理 |
| ユーザー | `src/User/` | ユーザー情報 |
| 友人関係 | `src/Friendship/` | ユーザー間の関係 |
| 暇時間 | `src/Availability/` | 暇時間の登録と参照 |
| 募集 | `src/Hosting/` | 募集に関する処理 |
| 通知 | `src/Notification/` | 通知の作成と送信 |
| アカウント削除 | `src/AccountDeletion/` | アカウント削除の調整 |

## 製品の判断基準

予定の設定・調整にかかるユーザー負荷を可能な限りゼロに近づけます。一度入力した日時・対象を再入力させず、安全な初期値と Siri などの入口で操作を減らします。本人の参加意思、招待対象、公開範囲は推測で変更しません。プロジェクト共通の正本は [製品方針](../../.kiro/steering/product.md) です。
Siri とショートカットへの暇登録・区間削除・募集作成・取消の公開は [Siri 操作仕様](../../.kiro/specs/ios-siri-actions/requirements.md) に沿って実装しました。通常起動と Siri は共通の実Backend依存を使い、認証・失敗時も入力を保って画面へ引き継ぎます。実機での日本語 Siri とショートカットの成立確認は未実施です。

## 初版で確定した製品契約

- 認証はSign in with Appleを使い、独自パスワードを持たない。
- 友達は期限付き招待コード、申請、相手の承認で成立する。全ユーザー検索と連絡先同期は行わない。
- 暇時間は本人が予定を入れたい時間とし、15分単位・今後14日を対象にする。重なる・接する登録はOR統合し、範囲削除は選択区間だけを差し引く。新規枠の共有設定は「参加OKするまで非公開」に戻す。
- 暇登録、募集時共有、参加OK、予定確定は別の意思表示として扱う。
- ホストには参加OKした相手と選択時間だけを返し、未回答・辞退・友達の暇登録状況を返さない。
- 募集は暇登録と同じ時間軸で候補範囲を選び、選択した承認済み友達全員へ暇登録の有無に関係なく送る。未登録範囲の本人暇は募集と原子的に登録し、募集中の範囲だけを一般の暇と区別する。
- Pushは後続の補助機能とし、現段階でもアプリ内受信箱から招待へ回答できる。
- 通報、ブロック、運営の是正、アプリ内アカウント削除を初版の完成条件に含める。
- iOSは17以降、SwiftUI/TCA、Swift Testingを使用し、iOSテストではXCTestを使用しない。

詳細な受け入れ条件は `.kiro/specs/ios-*`、依存順は `.kiro/steering/roadmap.md` を正本とします。

## 引き続き未確定・外部準備が必要な事項

- 予定の最終確定、友達の暇の公開・照合、Push配信、削除ジョブ。
- 実Bundle ID、Apple Team、App Store Connectのアプリレコードと審査用アクセス方式。
- 公開する利用規約・プライバシーポリシー・問い合わせURL、運営担当者と通報対応手順。
- App Store年齢レーティングとPrivacy Labelの最終申告。

添付中の `freeMask`、`shareMask`、`private`、`share_on_hosting` は内部表現と公開表現を分離する説明例です。
これらの保存形式や値を今回の業務仕様として固定しません。
「4週間程度の初版開発」は方式選定の背景として提示されたもので、確定した納期ではありません。
